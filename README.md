# 挂钟日历（WallClock）

给旧安卓手机做的**天气 + 黄历 + 日历 + 时钟**全屏挂钟，用来当墙面挂历 / 桌面时钟长期挂机。

- **APK 位置**：`output/WallClock.apk`
- **兼容范围**：Android 4.4（API 19）～ Android 14，横竖屏自适应
- **包名**：`com.vincent.wallclock`　**版本**：1.8
- **无第三方依赖**：不依赖 Google Play 服务、不依赖任何第三方库，天气走免费无需 Key 的 Open-Meteo
- **4 个页面**：主时钟 / 今日黄历 / 天气详情 / 月历，左右滑动切换，停手自动回主页面
- **12 种时钟样式**：现代 / 辉光管 / 灯丝管 / VFD 荧光屏 / 翻页钟 / 全息 HUD / 点阵 LED /
  矩阵雨 / 霓虹灯管 / CRT 绿屏 / 雷达扫描 / 赛博朋克，
  带辉光强度滑杆；发光样式在浅色主题下会自动配一块同色系的底；翻页钟带真实的**翻片动画**
- **字一定看得清**：所有文字都不小于屏幕短边的 3.2%（约 360dp 屏上的 11sp）；
  副页字号由档位定死、**与当天有多少条内容无关**，装不下的部分上下滑，
  绝不把字缩成一条线；另有**老人模式**整体放大 35%
- **月历页的宜忌也走同一条规矩**：选中日详情面板里的字号固定，词条多就面板内上下滑
  （日历格子不动），右缘有细滚动条提示「下面还有」
- **副页内容不随时间变化**，所以副页不做每秒重绘；主页面只在开着秒数时秒级刷新（省电）

把时钟的高度压掉了，而时钟是**受高度限制**的（不是受宽度限制），
把预报挪走之后主时钟能明显变大。

右侧详情面板里的宜忌**字号是固定的**：词条多就往下排成更多行，排满面板就
**面板内部上下滑**（日历格子不动），右缘有一条细滚动条提示还有多少。

各副页同样自动重排）。

### 副页装不下怎么办：固定字号 + 上下滑

副页（黄历 / 天气详情）的内容条数是变化的：宜忌可能 30 项，也可能 3 项；
天气可能六张卡都有，也可能没有空气质量数据。

1.4 以前是"按固定百分比切卡片高度，塞不进就把字缩小"——结果就是
**内容越多字越小**（30 条宜忌的字比 3 条的小一半），这条规则本身就是错的：
今天的内容多，不代表今天就该看不清。

现在的规矩是三条：

1. **字号只由档位定**：`精简 / 自动 / 完整` 三档各自对应一个固定字号
   （短边的 5.2% / 4.4% / 3.8%，老人模式再放大）。**同一台机器同一档位，字号恒定**，
   跟当天有几条宜忌、有没有空气质量数据完全无关。
2. **档位同时决定显示哪些卡**：精简只留宜忌；自动加神煞方位；完整再加时辰。
   精简 ⊂ 自动 ⊂ 完整，宜忌在任何档位都保留。
3. **装不下的部分一页一页翻**：卡片按内容取**自然高度**（不再被压扁），
   超出一屏的部分**整页翻**，页顶总是对齐到某张卡的开头，不会把卡切成上下两半。
   标题行**吸顶**不动，右侧的滚动条画成一小段一页、当前页高亮。
   快速甩一下多翻一页，慢速松手就停在最近的一页。
   手势做了方向锁：一次滑动要么横向切板块、要么纵向翻页，不会中途变向。

主页面同样不再写死百分比：每一块先报"最少要多高"，剩下的高度按权重分，
时钟按"再高也不会更大"的高度报需求。于是**关掉天气、农历、预报后时钟会真的变大**，
而不是中间空一大块；竖屏时时钟也不会在白留的空白里缩着。

> 具体到这台机器上每档多大字、分几页，是纯算术问题，由
> `gen/Layout.java` + `gen/Cards.java` 算出，并被 `tools/TestLayout.java`
> 拿 16 种真实分辨率 × 标准/老人两档字号穷举验证（见第六节）。

### 字号层级：谁该大、谁该小，写死在一张表里

上面这条「字号固定」的规矩只解决了「什么时候变」，没解决「该多大」。
1.6 的实际情况是每个字号**就地拍**出来的一串系数：

| 位置 | 1.6 的系数 | 问题 |
| --- | --- | --- |
| 卡片标题（方位 / 神煞 / 时辰） | 0.85 | **比正文还小**，标题看着像注释 |
| 页面主标题（干支日） | 0.70 | **比正文还小**，整页最不重要的反而是标题 |
| 正文（词条、数值） | 1.00 | 参照系 |
| 字段标签 | 0.70 | 与正文只差 30% |
| 页脚 | 0.48 | 只比正文小一半，和正文糊在一起 |
| 徽标行 | 0.60 / 占 2.20em 高度 | 字很小、胶囊很大，空出来的高度是从正文身上挤的 |

把这七个数排一排就会发现：**最高和最低只差 2.1 倍，中间还夹着两处倒挂**。
所以看过去什么都很重要，等于什么都不重要——这就是「该大的不大、该小的不小」。

1.7 把「谁比谁大、大多少」从各处收进 `gen/Type.java` 一张角色表：

| 角色 | 系数 | 用在哪 |
| --- | --- | --- |
| HERO | 1.58 | 一屏里唯一的「一眼看过去」的量：温度、AQI |
| TITLE | 1.32 | 页面主标题：干支日、月份 |
| HEAD | 1.12 | 卡片标题 |
| BODY | 1.00 | 正文：词条、数值、描述 |
| LABEL | 0.84 | 字段标签、表头、日期 |
| NOTE | 0.68 | 注释：吸顶辅助行、时间刻度、天气描述 |
| FOOT | 0.50 | 页脚：数据来源 |

两条取值原则：

- **顶上去、底不动**。只把上面几级拔高、下面几级基本留在原地（NOTE / FOOT 与
  改造前的 0.62 / 0.48 几乎持平），对比度就出来了。七级等比放大只是"整页字都变大"，
  层级还是平的。
- **高度跟着角色走**。把卡片标题从 BODY 提到 HEAD，卡片必须同时变高，
  否则 `Layout.floorFor` 会把它压回去——表现就是"该大的地方其实没大"，
  而且从代码上完全看不出来。所以每张卡的**固定高度**（内边距 + 标题 + 网格）
  也由同一张表算，见 `Cards.textRows` / `Cards.chromeH`。

顺带把固定区的留白还给了内容：徽标行从 2.20em 降到 1.06em、页脚从 1.70em 降到
0.75em，两者合计省下约三成固定区高度。

### 顺带修掉的一类问题：文字叠字

「字有下限」这条规矩有个副作用：下限是按**屏幕短边**算的，而各块分到的高度是按
**版式**算的，两者互不相干。一旦某块的高度装不下下限字号，缩字就会在下限处停下，
文字该多高还是多高 —— 表现就是相邻两行压在一起。

v1.6 从两头一起修：

1. **结构性护栏**：`Layout.floorFor` 给下限再加一道夹子 ——
   下限不得大于「分到的高度 ÷ 1.2」（1.2 是一行文字实际占高与字号的比值）。
   宁可这一行字小一点，也不叠在一起。
2. **高度跟着字号走**：副页的吸顶标题 / 徽标行 / 页脚高度从「屏幕百分比」改成
   「角色行高的固定倍数」，口径统一放在 `Cards.A_HEAD_ROLES` / `A_FOOT_PAD` /
   `PILL_PAD` / `W_FOOT_PAD` 里。这两套数字一旦绑在一起，横屏和大字号下就再也塞不破了。
3. **表格型内容不再按格子高度二次切分**：指标格 / 生活指数格 / 污染物格以前是
   「格子高的 36% 放名称、54% 放数值」，那又是一套和文字无关的数字。现在改成
   按角色行高自上而下摆，多余的高度留在格子底部当呼吸。
4. **字号再加页高上限**：副页字号额外不超过页高的 5.6%（按档位同比缩放），
   保证那些固定区最多占半屏。

### 1.8 补的四处

1. **首页农历行放大到正文级**。以前竖屏把农历、节气、倒计时挤成一行居中，
   只能靠缩字号将就宽度，越挤越小；横屏给的高度也偏紧。现在横竖屏一律**两行**、
   字号取 `Type.BODY` 定死（屏幕短边的固定比例），一行放不下就省略号收尾 —
   **不再动字号**。行高由 `HOME_LUNAR_ROLES` 声明，和副页是同一套口径。
2. **设置页有了返回按钮**。顶部一条吸顶的「‹ 返回」，滚多远都能一键回挂钟；
   设置清单最末也补了一个「返回挂钟界面」大按钮。以前从挂钟点进设置，
   界面上找不到任何退回去的线索，只能摸系统返回键。
3. **月历页的宜忌不再缩字，装不下就面板内滚动**。选中日详情面板以前整块按
   面板高度乘系数（`ih * 0.20` 给标题、`bodyH * 0.62` 给词条），面板矮字就小——
   词条一多必然被压。现在面板里每一块的高度都由 `gen/Type` 的角色算自然高度，
   按顺序往下摆；总高超过面板可视高就**面板内部上下滚**（日历格子不动），
   右缘有一条细滚动条。面板内各块的量高与绘制共用 `detailBlocks()`，
   不会出现「量出来说不用滚、画出来却缺一截」。
4. **翻页钟真的会翻页了**，见下面「时钟样式」一节。

### 12 种时钟样式

设置 → 时钟 → 「时钟样式」，改完即时生效：

| 样式 | 长什么样 | 发光 | 浅色主题下的底 |
| --- | --- | --- | --- |
| 现代 | 原来的无衬线粗体 | 否 | — |
| 辉光管 | 橙红霓虹，管里能看到没点亮的其它数字电极 | 是 | 暖米色 |
| 灯丝管 | 暖橙七段，段间留缝，像陶瓷封装的 Numitron | 是 | 浅橙 |
| VFD 荧光屏 | 青绿冷光七段，先画暗骨架再点亮的段 | 是 | 淡青 |
| 翻页钟 | 机械翻页牌，上下两半带中缝和厚度，**换数字时真的会翻** | 否 | 浅灰卡片 |
| 全息 HUD | 青蓝细线字 + 色差 + 扫描线 + 四角框 | 是 | 淡蓝 |
| 点阵 LED | 5×7 红色点阵，车站大屏的味道 | 是 | 淡红 |
| 矩阵雨 | 荧光绿数字，背后是逐秒下落的数码雨 | 是 | 淡绿 |
| 霓虹灯管 | 品红霓虹，多层辉光 + 白色内芯 + 管子上缘反光 | 是 | 淡粉 |
| CRT 绿屏 | 绿磷光 + 扫描线 + 上下暗角 + 红蓝色差，老终端那味 | 是 | 淡绿 |
| 雷达扫描 | 青色，上下边缘刻度 + 一条每 60 秒扫一遍的竖直光带 | 是 | 淡青 |
| 赛博朋克 | 青 / 品红错位描边 + 背后的网格，霓虹招牌色 | 是 | 淡蓝 |

配套的三条设计决定：

- **浅色主题不糊光晕**：亮底上画一圈光只会显得脏。所以发光样式在浅色主题下
  会自动带一块**同色系的浅底板**，数字改用该样式的深色版实心画——
  辉光管配暖米、VFD 配淡青、点阵配淡红，各配各的。桌面回归断言
  「深色底板够暗、点亮色够亮」「浅色底板够浅、点亮色够深」，一共 12 种样式 × 2 主题。
- **每个字符固定步进**：七段和点阵都不是等宽字形，步进宽度由
  `ClockSpec.advance` 给死，所以秒数从 9 跳回 0 时整块不会左右抖。
- **翻片只翻变了的那一位**：翻页钟把上一次的时间串一起传进绘制层，逐位比对，
  只有真的变了的那位才走翻片动画（下半张立刻换新数字、上半张过半换、翻片绕中缝折叠），
  没变的位置保持静止——整块乱翻反而像故障。动画 340ms，跑完就停，
  不会为了好看让挂钟整天满帧重绘。

**科技感这一组为什么不做满帧动画。** 矩阵雨的雨点、雷达的光带本来都可以每秒几十帧地跑，
但这台机器是要亮一整天的。所以它们的推进节拍刻意跟着**整秒**走（和挂钟本身的刷新同频），
只在翻片那 340ms 里自驱补帧。

「辉光强度」滑杆（0–100%，默认 60）只影响发光样式，0 就是完全不发光。
字模（七段段掩码、5×7 点阵位图）在 `gen/ClockSpec.java` 里，被
`tools/TestClock.java` 逐位穷举验证——写错一位在真机上只是"某个数字缺一笔"，肉眼很难查。

## 二、安装

1. 把 `WallClock.apk` 传到手机（微信文件传输 / 数据线 / 网盘都可以）。
2. 手机上点开安装，若提示"未知来源"，在弹窗里选择允许安装。
3. 首次打开会申请定位权限：
   - **允许**：自动定位到你所在城市，换地方也能用；
   - **拒绝也没关系**：点右下角齿轮 → 城市与天气源 → 当前城市 → 从内置城市列表选择（约 180 个城市，离线可用），或联网搜索、手填经纬度。

### 断电 / 重启后怎么自己回来

这一块有三个独立机制，建议全部打开：

1. **开机自启**：带开机广播接收器，同时收标准 `BOOT_COMPLETED`、
   `LOCKED_BOOT_COMPLETED`（加密机器上解锁前就能抢跑）和两种写法的
   `QUICKBOOT_POWERON`（部分 ROM 的"快速开机"只发这个，不标准的）。
   开机后不立刻启动，而是延迟 7 秒等系统起稳，避免白屏或被拦。
   关掉这个开关会**同时停用接收器**，系统开机不再唤起本应用（真省电，不是只存个布尔值）。
2. **看门狗自愈**：每 15 分钟自检一次，发现界面不在前台就重新拉起来。
   用 `setAndAllowWhileIdle` 的不精确闹钟——能穿透 Doze，又不需要
   `SCHEDULE_EXACT_ALARM` 这个受限权限。**注意能力边界**：Android 10 以后系统
   限制后台应用直接启动界面，这一招在 Android 9 及更老的机器上可靠
   （而这恰好是"旧手机改挂钟"的主要人群），10+ 上可能被系统忽略。
3. **设为默认桌面**（最可靠）：把本应用设为默认桌面后，按 Home 键就回挂钟，
   也完全绕开后台启动限制。设置页里有直达这个选择框的入口。

**关于"断电后自动开机"**：应用无权让手机关机后自己通电开机——那需要 root
改引导层或内核，任何普通应用都做不到。可以这样绕：

- 在系统「设置 → 电源 / 电池」里找**「接通电源自动开机」**之类的选项，部分机型有这个开关；
- 用带开关的插座，再串一个**充电宝 / UPS** 垫一层：短时断电由电池扛过去，手机根本不会关机；
- 打开系统的**「电池保护 / 充电上限」**，避免长期满电把电池撑坏。

另外强烈建议**关掉锁屏密码**：有密码的机器上，加密存储要等首次解锁后才发开机广播，
挂墙的屏会白很久。设置页「开机与自愈」里有直达系统安全设置页的入口。

## 四、设置项一览（共 55 项，改完即时生效）

- **显示内容**：天气 / 天气详情 / 未来三天预报 / AQI / 日出日落 / 城市名 / 电量
- **副页与翻页**：今日黄历页 / 天气详情页 / 月历页 / 自动回到主页面（不自动～5 分钟）/ 防误触 / 黄历内容（完整 / 精简）/ 月历一周起始（周日 / 周一）
- **阅读与字号**：老人模式（大字号，整体放大 35%）/ 副页信息量（精简 / 自动 / 完整）
- **时钟与日期**：24 小时制 / 显示秒 / 日期 / 星期 / 农历 / 节气与节日 / 节日倒计时 /
  时钟大小（60%～140%）/ **时钟样式**（现代 / 辉光管 / 灯丝管 / VFD / 翻页钟 / 全息 HUD /
  点阵 LED / 矩阵雨 / 霓虹灯管 / CRT 绿屏 / 雷达扫描 / 赛博朋克）/
  **辉光强度**（0%～100%，只对发光样式生效）
- **外观**：主题（跟随昼夜 / 固定深色 / 固定浅色）、深色时段起止、用真实日出日落判断、环境变暗自动切深色、光线触发阈值（0～120 lux）、屏幕方向
- **屏幕与防烧屏**：屏幕常亮、常规亮度、夜间自动调暗、夜间起止、夜间亮度、夜间熄屏、防烧屏位移、位移周期、位移幅度、显示设置齿轮
- **城市与天气源**：定位方式（自动 / 手动）、城市选择（内置列表 / 联网搜索 / 手填经纬度）、刷新间隔（10～180 分钟）、温度单位
- **开机与自愈**：开机自动启动、看门狗自愈（每 15 分钟自检）、设为默认桌面入口、应用系统设置页入口、锁屏密码设置页入口、断电自动开机的说明
- **系统**：电池优化白名单入口、恢复默认设置

进设置的方式：**点右下角小齿轮**，或**长按屏幕任意位置**。
把"显示设置齿轮"关掉后，就只剩长按入口；开启"防误触"后长按需 1.5 秒。

**老人模式**只改字号的"档位"，不改布局代码：副页按档位取固定字号、再整体放大 35%，
于是每屏能装下的条目变少、需要**上下滑**的距离变长
——这正是想要的取舍：**宁可多滑一点，也不要字小到看不清**。

**省电**：主页面只在"显示秒"打开时才每秒重绘；关闭秒数后只按分钟刷新一次。
副页内容不随时间变化，翻到副页后停止重绘（原来是无条件每秒一次，
挂墙上一整天就是 8 万多次无谓重绘）。时钟的唤醒也按秒对齐，
顺带减少了闹钟抖动。

**设置页也支持横屏**：方向跟随"外观 → 屏幕方向"这一项，和主界面保持一致，
横放的挂钟点开设置不会突然转成竖屏。横过来宽度够（≥600dp）时自动排成**左右两列**，
不用一路往下滑；配色跟昼夜主题走，深色模式下不会闪一屏白。

**环境变暗自动切深色**：靠手机的光线传感器判断，房间关灯后即使还在白天也会切黑底。
触发阈值可调（0～120 lux，0 = 关闭），并且带 **3 倍滞回**——阈值设 20 lux 时，
要亮到 60 lux 才切回浅色，避免光线在临界点抖动导致背景反复闪。
只做"变暗 → 深色"这一个方向：夜里开着灯仍然保持深色，不会因为灯亮就被顶回白底。
选"固定深色"时本来就恒为深色，此时不会注册传感器（省电）。
**没有光线传感器的设备**这一项不生效，设置页会直接标注出来。

### 数据可信度（都做过交叉校验）

- **农历**：用 `lunardate` 与 `cnlunar` 两个独立实现交叉比对 1900–2099 全部 73018 天，与权威闰月表逐月核对 1900–2031 年**零差异**；锚点校验 1900 年编码等于经典值 `0x04bd8`；春节日期抽查 2023/2024/2025/2026 全对。
- **节气**：用权威交节时间校验（2026 年芒种 = 6 月 5 日 23:48，验证 2026–2031 六年全部命中）。注意：网上流传的"简化节气公式"在 2026 年芒种上会算错一天，本项目不用它。
- **Java 实现回归测试**：`LunarCalendar` 逐日比对 73018 天基准，**0 处不符**，并额外断言闰月、除夕、母亲节/父亲节、干支生肖、范围外降级等定点行为。
- **黄历**：以 timecha.com / 8s8s.net / ima.qq.com **三源互证**的 3 个样本（2026-09-15、2026-09-16、2026-01-01）逐字段断言，覆盖干支、建除、值神、星宿、冲煞、纳音、彭祖百忌、胎神、喜财福神、贵人、吉神、凶神；再做 1900–2099 全量不变量扫描。起例口径与样本见 `tools/ALMANAC_NOTES.md`。
- **二十八宿**：网上流传两套起法，其中"三合局起宿法"会破坏"房/虚/昴/星恒为星期日"这条铁律。本项目用实测数据反推的口径 `((JDN + 12) mod 28)`，全量扫描 0 违例。
- **版式算术**：`gen/Layout.java` + `gen/Cards.java` + `gen/Type.java` 是不依赖 Android 的纯算术层，负责"副页固定字号、卡片自然高度、滚动范围、分档显示哪些卡、整页翻页的停靠点、可读下限的护栏"。桌面回归穷举 16 种真实分辨率（320×480 ～ 2560×1440，横竖各半）× 标准/老人两档字号，并断言"**同档位字号恒定、与内容量无关**""滚动范围正确""卡片不重不漏""档位严格递增""**页顶对齐到卡片且一定能滚到底**""**下限装不进分配高度时会被压到放得下**"，共 **95.2 万项断言，0 失败**。
- **字号层级表**：`gen/Type.java` 把全部字号收敛成 HERO/TITLE/HEAD/BODY/LABEL/NOTE/FOOT **七级阶梯**，并写成硬约束——阶梯严格递减、相邻两级至少差 `MIN_STEP`（1.10）、最高/最低至少差 `MIN_CONTRAST`（2.40）。桌面回归断言"阶梯严格递减""相邻可分辨""首尾对比够强""`size/line` 代数自洽""非法输入（NaN/负数/0/无穷）统一降级为 BODY"。另断言每张卡片的**固定高度装得下它自己声明的那几行文字**，且天气固定区最多占屏高 45%。这两组共 **4.1 万项断言，0 失败**。
- **时钟样式算术**：`gen/ClockSpec.java` 是时钟样式的纯算术层，负责配色、七段段掩码、5×7 点阵位图、字符步进与字高反推。桌面回归断言"12 种样式的名字互不相同""10 个数字的段掩码互不相同且段数正确""点阵字模互不相同""同一串里数字等步进（防秒跳抖动）""**深色底板够暗、点亮色够亮；浅色底板够浅、点亮色够深**（12 种样式 × 2 主题）""放不下就返回 0 而不是溢出"，共 **23.6 万项断言，0 失败**。
- **夜间/主题与自启**：主题判定（含光照滞回）覆盖 6.3 万组参数；开机自启与看门狗是系统行为，无法桌面单测，改为在设置页里给出能力边界说明（见第三节）。
- **光线感应**：阈值与滞回判断同样是纯 Java（`gen/LightRule`），桌面回归覆盖 6.3 万组参数，并验证「光照单调变化最多切换一次」「滞回带内的抖动不会翻状态」，**0 失败**。
- **超出 1900–2099 年**：自动隐藏农历，只显示公历，不会显示错误数据。

> **关于宜忌**：干支、建除十二神、二十八宿、黄道黑道值神、冲煞、纳音、胎神、
> 方位、十二时辰吉凶都是历法上可唯一确定的定值；而"宜忌"在不同通书之间本就
> 有出入，本实现按各神煞的所宜所忌合成，并在页面上标注"仅供参考"。
> **请勿据此择日。**

### Android 4.4 上的 HTTPS 兼容

老机器上有两个独立的坑，缺一不可：

1. **TLS 1.2 默认没开**。API 19 的 `SSLContext` 默认协议是 TLSv1，服务端早已拒绝。
   代码里显式打开 TLS 1.2，并补上 4.4 上默认关闭的强加密套件（筛掉 NULL/RC4/DES/3DES/EXPORT/匿名）。
2. **系统信任库里没有 Let's Encrypt 的新根**。Open-Meteo 的证书链是
   `open-meteo.com ← YR2 ← Root YR ← ISRG Root X1`，而 `ISRG Root X1` 直到
   **Android 7.1.1（API 25）**才进系统信任库。所以 **API 19–24 都会在证书校验这步失败**，
   只修 TLS 1.2 是没用的。

解决办法是把这条链上的三张证书随 APK 带上（`src/.../gen/TlsAnchors.java`，由
`tools/extract_ca.py` + `tools/gen_tls_anchors.py` 生成），运行时用
"系统默认信任库 **或** 内置锚"的复合 TrustManager。既补上了缺的根，
又不会削弱对其它站点的校验强度（内置锚里只有 Let's Encrypt 新层级这三张证书）。

**注意**：根证书会过期。内置的 `Root YR` 有效期到 2028-09、`ISRG Root X1` 到 2035-06，
足够长期使用；但若将来 Open-Meteo 换到别的 CA 层级，需要重新抓链并重新生成
`TlsAnchors.java`（重新执行上面两个脚本即可）。设置页「关于」里会显示当前设备
实际走的是哪条路径。

```powershell
# 1) 重新生成数据表与图标（可选）
python tools/gen_tables.py
python tools/gen_icon.py

# 2) 只有在需要更新内置根证书时才跑（抓链 -> 出 Java）
#    python tools/extract_ca.py
#    python tools/gen_tls_anchors.py

# 3) 桌面回归测试（可选，但建议）
$jdk = "C:\Users\vincent\.workbuddy\binaries\android-toolchain\jdk17\jdk-17.0.13+11\bin"

& "$jdk\javac.exe" -encoding UTF-8 -d build/lunartest src/com/vincent/wallclock/gen/LunarTables.java `

```

嫌麻烦就一条命令跑完全部（5 个桌面回归 + 2 个产物校验 + 签名/清单），
任何一项失败整体 exit 1：

```powershell
powershell -ExecutionPolicy Bypass -File tools/verify_all.ps1
```

日志落在 `build/verify_all.log`。

> **改这两个 .ps1 时注意编码**：Windows PowerShell 5.1 对**没有 BOM** 的
> `.ps1` 会按系统 ANSI（本机是 GBK）解析，脚本里的中文会变成乱码并直接报
> `Unexpected token`。用记事本/VS Code 另存为 **UTF-8 with BOM**，
> 或执行下面这句补 BOM：
>
> ```powershell
> $p = "tools\verify_all.ps1"
> $c = [IO.File]::ReadAllText($p, (New-Object Text.UTF8Encoding($false)))
> [IO.File]::WriteAllText($p, $c, (New-Object Text.UTF8Encoding($true)))
> ```
>
> `build.ps1` 全 ASCII，不受影响。

### 签名与密钥

**仓库里不含私钥**：`keystore/` 已在 `.gitignore` 中排除，别人拿不到你的密钥。
`tools/build.ps1` 在首次构建时若发现密钥不存在，会自动用 `keytool` 生成一个
（口令 `wallclock`，仅供本地自用），所以 clone 下来直接就能构建出可安装的 APK。

两点注意：

- 要上架应用商店，请换成自己的正式签名，并妥善备份。
- **换了密钥就等于换了应用身份**：签出来的 APK 与旧版签名不一致，
  已安装的手机会拒绝覆盖升级，必须先卸载再装。所以在多台机器上构建时，
  请把同一个 `wallclock.jks` 备份好带过去。
